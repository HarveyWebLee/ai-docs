# 002 · 思维链与推理

> 本文用大白话回答：为什么让模型"一步步想"就答得更准？思维链、自洽性、ReAct 这几个词分别在说什么？怎么让模型"想清楚再答"？
>
> **零基础读法**：先只看第一、二节建立画面；第三节对照表格理解三种技巧；第五节有完整例题；想动手试，复制第六节里的 prompt 到任意聊天模型即可。

## 一、一句话先说清

**思维链（Chain-of-Thought，简称 CoT，"让模型把思考过程一步步写出来"）= 逼模型先打草稿、分步推理，而不是一口气蹦出答案。**

一句大白话：**"请一步步思考"这句魔法咒语，往往就能让模型变聪明。**

补充两个你会常听到的词（先混个脸熟，后面会细讲）：

- **自洽性（Self-Consistency）**：同一道题让模型**多想几遍、再投票**，减少"某一次碰巧想歪了"。
- **ReAct（Reason + Act，推理 + 行动）**：不只"想"，还要**查资料、算数、调 API**，想一步、做一步、再看结果再想。

## 二、打个比方：算数学题要不要写草稿

让模型做一道复杂数学题：

- 如果逼它**脱口而出答案**（心算），很容易算错；
- 如果让它**一步步写出推理过程**（打草稿），正确率会显著提升。

这跟人做题一模一样：难题不打草稿、想一步跳到答案，最容易出错；把步骤写下来，每一步都简单可控，反而更稳。

**为什么对模型也管用？** 大模型本质是个**"下一个词预测器"**——根据已经写出来的字，不断猜下一个字该是什么。写出中间步骤，等于给自己铺了一条通往正确答案的"思考轨道"：每一步都基于前一步，把"一步登天"拆成"步步为营"，出错概率自然降下来。

| 你做题 | 模型做推理 |
| --- | --- |
| 心算大题 | 直接输出最终答案（无 CoT） |
| 草稿纸分步算 | 先写推理步骤，再写答案（有 CoT） |
| 算两遍对一下 | 采样多条推理链再投票（自洽性） |
| 查公式表、用计算器 | 调用搜索/计算器工具（ReAct） |

## 三、它到底解决什么问题

### 问题 1：复杂推理"一步到位"太容易翻车

对于要拐好几个弯的题（数学、逻辑、常识推断），直接要答案就像让人"不打草稿口算大题"。

| 做法 | 朴素做法（直接要答案） | 更好做法（思维链） |
| --- | --- | --- |
| 面对多步推理题 | 一口气蹦答案，易被数字/干扰项带偏 | 拆成有序小步，每步都简单不易错 |
| 典型触发方式 | 只问"答案是多少？" | 加一句"请一步步思考"或示例里带推理过程 |

触发思维链有两种常见方式：

- **少样本 CoT（Few-shot CoT）**：在 prompt 里给 1~2 个**完整示范**——"问题 → 推理步骤 → 答案"，让模型照着格式分步写。
- **零样本 CoT（Zero-shot CoT）**：不给示范，只在问题后面加一句 **"让我们一步步思考（Let's think step by step）"** 就能触发——这是 2022 年论文里验证过的高效技巧。

要点：CoT 主要对**多步推理**任务有效（数学、逻辑、常识推断）；问"法国首都是哪？"这种一步题，加 CoT 收益很小。

### 问题 2：一条推理链也可能"碰巧走错路"

哪怕分了步，模型偶尔还是会沿着一条错误路径走到底。怎么办？——**多问几遍再投票**。

这就是**自洽性（Self-Consistency）**：

1. 对**同一问题**，用较高温度（temperature）采样 **5~10 条**不同的思维链；
2. 每条链可能得到不同最终答案；
3. 对最终答案**多数投票**，取出现次数最多的那个。

> 直觉：一道题若真有唯一正确答案，不同正确路径往往会落到**同一个答案**；错误推理则各错各的、答案分散。所以"多数票"更可靠。**代价**：要调用模型多次，成本和延迟都上升。

### 问题 3：光"想"不够，有些事得"动手做"

纯推理解决不了"需要查最新资料、精确计算"这类问题——这时要让模型**边想边用工具**。

这就是 **ReAct（Reason + Act）**：把"思考"和"行动"交织成一个循环：

$$
\text{Thought（想）} \to \text{Action（用工具）} \to \text{Observation（看结果）} \to \text{Thought} \to \dots
$$

模型先思考该做什么，再调用工具（如搜索、计算器），观察返回结果，再继续思考——这是构建 [Agent](./004-Agent架构与评估.md) 的核心推理范式（工具细节见 [003 · 工具调用与函数调用](./003-工具调用与函数调用.md)）。

## 四、专业视角（与大白话对齐）

- **思维链（CoT）**：在提示中要求模型显式生成推理步骤（而非直接输出结论）的技术。对齐前面：就是"逼模型打草稿、分步走"。分为**少样本 CoT**（示例含推理过程）与**零样本 CoT**（仅加一句"一步步思考"）。
- **自洽性（Self-Consistency）**：对同一问题采样多条推理路径，对最终答案做多数投票。对齐前面：就是"多问几遍再投票，靠少数服从多数提高可靠性"。
- **ReAct（Reason + Act）**：将推理（Thought）与工具调用（Action）及其结果（Observation）交替进行的循环范式。对齐前面：就是"边想边动手、看着结果再想下一步"。

## 五、案例解析

### 5.1 CoT 如何救回一道应用题

**问题**："小明有 5 个苹果，买了 3 袋、每袋 4 个，又吃了 2 个，现在有几个？"

- **直接作答**（无 CoT）：模型可能被数字干扰，脱口而出"12"或其它错误值。
- **思维链作答**：
  1. 初始有 5 个；
  2. 买了 3 袋 × 4 个 = 12 个，共 5 + 12 = 17 个；
  3. 吃了 2 个，17 − 2 = **15 个**；
  4. **答案：15 个**。

把计算拆成有序小步后，每一步都简单不易错。可用心算验证：5 + 12 − 2 = 15 ✔

### 5.2 自洽性：同一题采样三条链

假设对上面苹果题采样三条推理（简化示意）：

| 第几次采样 | 最终答案 |
| --- | --- |
| 链 1 | 15 |
| 链 2 | 15 |
| 链 3 | 12（某步乘加搞混） |

投票结果：**15 得 2 票，12 得 1 票 → 输出 15**。单跑链 3 会错，自洽性把偶然错误压下去了。

### 5.3 ReAct 迷你对话：查天气

**用户**："北京明天会下雨吗？"

```
Thought: 需要查实时天气预报，我不能凭记忆瞎说。
Action:  weather_api(city="北京", date="明天")
Observation: {"condition": "小雨", "high": 18, "low": 12}
Thought: 观测结果是小雨，可以回答了。
Answer:  根据预报，北京明天有小雨，气温 12~18°C，建议带伞。
```

对齐：Thought = 想；Action = 调工具；Observation = 看返回；最后再 Answer。

## 六、零基础怎么试（可直接复制的 Prompt）

**零样本 CoT**（复制到任意聊天模型）：

```text
问题：一个水池有两个进水管，A 管单独注满需 6 小时，B 管单独注满需 3 小时，两管同时开多久注满？
请一步步思考，再给出最终答案。
```

**少样本 CoT**（在问题前加示范）：

```text
示例：
问：3 个苹果加 2 个苹果等于几个？
思考：3 + 2 = 5
答：5 个

现在请同样格式回答：
问：……（你的问题）
```

## 七、常见误区与边界

- **误区："CoT 对所有任务都有效"**：对简单直接的任务，CoT 收益有限甚至增加冗余；它主要利好多步推理。
- **误区："写了步骤就一定对"**：模型可能给出**看似合理实则错误**的推理（幻觉式推理），步骤正确性仍需校验或配合工具/投票。
- **误区："自洽性永远比单次 CoT 好"**：多数投票在"答案空间小、错误分散"时有效；若模型系统性偏见，可能**集体错向同一方向**。
- **边界**：需要精确计算或实时信息时，应让模型**调用工具**而非纯靠"心算"（见 [003](./003-工具调用与函数调用.md)）。

## 九、一句话总结

- CoT 让模型分步推理，显著提升多步任务正确率；自洽性用多路投票增强可靠性；ReAct 把推理与工具行动交织，是 Agent 的核心范式。
