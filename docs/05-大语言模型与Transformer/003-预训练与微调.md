# 003 · 预训练与微调

> 本文用大白话回答："预训练 + 微调"这套两阶段打法到底是什么？为什么"自监督"不用人工标注也能学到知识？LoRA 这类省钱微调法，是怎么做到用消费级显卡就能调大模型的？
>
> **零基础读法**：先读第二、三节三张对照表建立"上学→上岗→只训关键技能"画面；第四节公式集中放；第五节"续写机变聊天助手"案例必看；跑 demo 看参数量对比；第七节自测后再看总结。
>
> 读完你会知道：训练大模型很像"**先海量自学打底，再上岗前专项培训**"，而 LoRA 则是"**只培训关键技能、不重造一个人**"的省钱妙招。

## 一、一句话先说清

**"预训练 + 微调" = 先让模型海量自学、打好通用底子（预训练），再用少量专业数据做针对性培训、让它胜任具体活儿（微调）。**

- **预训练（Pre-training）**：读遍互联网级别的文本，把语言规律和世界常识吃进肚子；
- **微调（Fine-tuning）**：在这个通用底子上，用特定任务的数据"点一下技能树"；
- **PEFT（Parameter-Efficient Fine-Tuning，参数高效微调，如 LoRA）**：微调时**只动极少量参数**，把成本压到最低。

| 阶段 | 数据从哪来 | 主要成本 | 得到什么 |
| --- | --- | --- | --- |
| 预训练 | 海量无标注文本 | 算力（贵） | **基座模型**（会语言、有常识） |
| 微调 | 少量任务标注 | 算力 + 标注（相对便宜） | **任务专用模型**（会聊天、会分类…） |
| LoRA 等 PEFT | 同微调 | 显存/存储大降 | 每个任务只存一小块权重 |

## 二、打个比方：培养一名员工

训练一个大模型，特别像**培养一名员工**：

| 培养员工的阶段 | 训练模型的对应 | 干什么 | 成本在哪 |
| --- | --- | --- | --- |
| 上学阶段，海量通识自学 | **预训练** | 读海量文本、自学语言与常识 | 主要是算力，不用人工标注 |
| 入职后的岗位专项培训 | **微调** | 用少量任务数据教它干具体活 | 数据量小，成本可控 |
| 只培训关键岗位技能 | **PEFT / LoRA** | 冻结大部分能力，只训一小撮参数 | 成本极低，消费级显卡可跑 |

其中最妙的是预训练那句"**自己给自己出题**"：把一段话遮住一部分，让模型去猜被遮住的内容——猜对猜错都能立刻对答案。这样**根本不需要人来标注**，文本本身就是标准答案。

**和后面章节的关系**：预训练+微调做出"会说话的基座"；若要它**查资料再答**见 [004 RAG](./004-检索增强生成RAG.md)；若要它**答得更安全、更像人**见 [005 对齐与 RLHF](./005-对齐与RLHF.md)。

## 三、它到底解决什么问题

**问题 1：想让模型有知识，可人工标注贵到天上去，怎么办？**

朴素做法是"人工标好每条数据再喂给模型"，但互联网级别的文本要人一条条标，根本标不完、也标不起。

| 做法 | 谁来出题/给答案 | 成本 |
| --- | --- | --- |
| 朴素做法：人工标注 | 靠人一条条标 | 天价，标不完 |
| 更好做法：自监督 | 从文本自身构造题目（遮词让它猜） | 几乎零标注成本 |

解法：**自监督学习（Self-supervised Learning，"从数据自己造标签"）**——"从数据本身构造监督信号"，把文本挖个空当题目，答案就是被挖掉的原文。

**问题 2：每个新任务都从头训一个大模型？太浪费了**

朴素做法是"每来一个任务就重训一整个大模型"，又慢又费钱，学到的通用能力还白白重来一遍。

| 做法 | 每个新任务怎么办 | 代价 |
| --- | --- | --- |
| 朴素做法：从零训练 | 重头训一个完整大模型 | 算力、数据都烧不起 |
| 更好做法：微调 | 在预训练底子上接着训 | 快、省，还借用了通识 |

解法：**微调**——站在预训练的肩膀上，只补上任务专属的那部分本事。

**问题 3：微调虽好，但全参数微调依然很贵、每个任务都要存一份完整模型**

| 做法 | 训练量 / 存储 | 适用 |
| --- | --- | --- |
| 朴素做法：全参数微调 | 更新所有参数，每个任务存一整份模型 | 效果好但显存/存储开销大 |
| 更好做法：PEFT（LoRA） | 只训不到 1% 的参数，每任务只存一小块 | 平民显卡也能微调 |

解法：**参数高效微调（PEFT）**，代表就是 LoRA。生成式图像场景（Stable Diffusion 画风/角色）的 LoRA 详见 [10/005 LoRA](../10-生成式AI/005-LoRA低秩微调.md)。

## 四、专业视角（与大白话对齐）

### 4.1 预训练：自监督学习

**自监督**的精髓是"**从数据本身构造监督信号**"，无需人工标注。两种最常见的出题方式：

- **自回归语言建模（Autoregressive LM，GPT 系）**：给定前文，预测下一个词，目标是最大化
$$
\sum_t \log P(x_t\mid x_{<t})
$$
> 一句话对齐：这个式子就是"**遮住后文、拿前文 $x_{<t}$ 去猜下一个词 $x_t$，猜得越准（概率越大）越好**"。GPT 从左到右读，像自动补全短信。

- **掩码语言建模（Masked LM，BERT 系）**：随机遮住句子里的部分词，再让模型预测被遮住的词。$\to$ 就是"完形填空"，可以同时看左右文。

预训练的损失通常是词表上的**交叉熵（Cross-Entropy，衡量预测分布与真实词的差距）**（见 [01-数学与理论基础/004 信息论](../01-数学与理论基础/004-信息论基础.md)）。

| 预训练目标 | 代表模型 | 擅长 |
| --- | --- | --- |
| 下一个词预测 | GPT 系列 | 生成、对话、续写 |
| 完形填空 | BERT 系列 | 理解、分类、抽取 |

### 4.2 微调（Fine-tuning）

在预训练权重 $\theta_0$ 的基础上继续训练：

- **SFT（Supervised Fine-Tuning，监督微调）**：用"**指令 → 理想回答**"的配对数据，教模型学会按指令作答。$\to$ 就是"手把手教它：看到问题要回答问题"。
- **全参数微调**：更新**所有**参数 $\theta$，效果好，但显存/存储开销大（每个任务都得存一份完整模型，7B 模型一份就十几 GB）。

**学习率习惯**：微调时学习率通常比预训练**小很多**，避免几步就把通识"冲掉"（灾难性遗忘）。

### 4.3 参数高效微调（PEFT）与 LoRA

**LoRA（Low-Rank Adaptation，低秩适配）**的核心思想：**原来的权重 $W_0$ 冻住不动**，只额外学习一个"**低秩增量**"$\Delta W = BA$（其中 $B\in\mathbb{R}^{d\times r}$，$A\in\mathbb{R}^{r\times k}$，秩 $r\ll d,k$，即 $r$ 很小）：

$$
W = W_0 + \Delta W = W_0 + BA
$$

前向时：$\mathbf{y} = W_0 \mathbf{x} + B A \mathbf{x}$——旧本事照旧，旁边贴一小片新参数做修正。

> 一句话对齐：这个式子就是"**旧本事 $W_0$ 原封不动，只在旁边贴一小片新参数 $BA$ 去补充**"。因为 $r$ 很小，$A$、$B$ 参数量 $r(d+k)$ 常常不到原矩阵 $dk$ 的 1%。

只训练 $A$、$B$ 这一小撮参数，就能拿到接近全参数微调的效果，而且每个任务只需存一份很小的 LoRA 权重（几 MB 到几百 MB）。这正是**消费级显卡也能微调大模型**的关键技术。

| 方法 | 可训练参数 | 每任务存储 |
| --- | --- | --- |
| 全参数微调 | 100% | 整模型 |
| LoRA（$r=8$） | 通常 < 1% | 仅 $A,B$ 矩阵 |

## 五、案例解析：从"续写机"到"聊天助手"

拿一个**只做过预训练**的 GPT，给它输入"如何学习 Python？"，它可能**并不会回答你**，而是接着往下续写："如何学习 Java？如何学习 C++？"——因为它本质只是个"下一个词预测器"，学到的是"**把文本补全下去**"，而不是"回答问题"。

| 模型阶段 | 你问"如何学 Python？" | 它更像 |
| --- | --- | --- |
| 仅预训练 | 续写"如何学 Java？…" | 搜索引擎联想条 |
| SFT 后 | 分点给学习建议 | 客服/助手 |
| + RLHF 后 | 更安全、更符合人类偏好 | 产品级对话 |

要把它变成会**遵循指令**的聊天助手，得再走两步：

1. **SFT**：用大量"指令 → 理想回答"的样本微调，教它"看到问题就去回答问题"；
2. （进一步）**对齐 / RLHF**：用人类偏好继续优化回答的质量与安全性（见 [005 · 对齐与 RLHF](./005-对齐与RLHF.md)）。

这也解释了为什么"**基座模型（base）**"和"**对话模型（chat/instruct）**"表现差这么多——它们经历的训练阶段根本不一样。下载模型时看名字：`Llama-3-8B` 多为基座，`Llama-3-8B-Instruct` 为 SFT/对齐后的对话版。

## 六、常见误区与边界

- **误区："预训练需要人工标注"**：不对。预训练是**自监督**，标注成本几乎为零，钱主要花在算力和数据清洗上。
- **误区："微调越多越好"**：在小数据上过度微调，容易**灾难性遗忘**（把原来的通用能力丢了）并且过拟合——表现为训练集很好、换问法就崩。
- **误区："LoRA 一定无损"**：LoRA 在多数任务上接近全参数微调，但遇到极端任务、需要大幅迁移能力时，仍可能有差距；$r$ 太小也会限制表达力。
- **边界**：预训练数据质量决定能力上限；微调只能"唤醒/对齐"已有能力，不能凭空注入模型没见过的知识（该用 [RAG](./004-检索增强生成RAG.md)）。

## PyTorch 可运行示例

安装 CPU 版 PyTorch（仅需一次）：

```bash
pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cpu
```

运行 PyTorch 版示例：

```bash
python code/05-大语言模型与Transformer/003-预训练与微调/demo_torch.py
```

**输出含义**：脚本模拟一个 $768×768$ 线性层上的 LoRA。你会看到：

- `全量 Linear 参数量：589,824`（$768×768$）——若全参数微调，这些都要更新、都要存一份；
- `LoRA 可训练参数量：12,288`（$r=8$ 时 $8×(768+768)$）——约为全量的 **2%**；
- `LoRA 冻结 base 参数量：589,824`——旧权重 $W_0$ 不动，对应公式 $W=W_0+BA$ 里冻住的那部分；
- `前向输出形状：(2, 768)`——批量 2、特征 768，说明 LoRA 层可以正常替代 Linear 参与训练。

## 八、一句话总结

- 两阶段范式：**自监督预训练**学通识（自己出题、不用人标），**微调**学专项；SFT 把"续写机"调教成"答题助手"。
- **LoRA 等 PEFT** 用一小片低秩增量大幅降低微调成本；生成式场景（Stable Diffusion 画风/角色）详见 [10/005 LoRA 低秩微调](../10-生成式AI/005-LoRA低秩微调.md)。
